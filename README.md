# Карта в дело

Чат-бот (+ мини-приложение) в MAX, который помогает подобрать мероприятие
по «Пушкинской карте» и напоминает, пока баллы не сгорели.

## Что входит в сдачу (чек-лист формата)

- `presentation.pdf` — презентация решения (первый слайд служебный, с местами
  под ссылки/токены для жюри — их нужно заполнить перед отправкой);
  `presentation.pptx` — тот же файл в редактируемом виде.
- `bot/`, `miniapp/` — исходный код чат-бота и мини-приложения.
- `bot/package.json` + `bot/package-lock.json` — файл зависимостей.
- `compose.yaml`, `bot/Dockerfile`, `.dockerignore`, `.env.example` — Docker-конфигурация.
- Этот `README.md` — назначение, сценарий, архитектура, переменные окружения,
  порты, зависимости, интеграции, работа с данными, сценарий проверки,
  примеры поведения, известные ограничения, порядок запуска/остановки.
- **Собственного API нет** — раздел «только для решений с собственным API»
  (OpenAPI, DATA-API.yaml и т.п.) не применяется.
- **Перед отправкой ещё нужно сделать (не автоматизируется отсюда):**
  зафиксировать версию в Git (commit hash) или архив с контрольной суммой;
  задеплоить бота и мини-приложение на реальные публичные адреса и вписать
  эти ссылки в служебный слайд презентации и в README вместо плейсхолдеров;
  вписать название команды и участников на 2-м слайде презентации.

## Назначение решения

Студент/школьник 14–22 лет с активной «Пушкинской картой» не имеет одного
удобного места, где можно быстро найти мероприятие под свои интересы,
бюджет баллов и дату, и не отслеживает остаток баллов до тех пор, пока они
не сгорают в конце года. Продукт закрывает это одним диалогом в MAX плюс
каталогом в мини-приложении.

## Основной пользовательский сценарий

1. Пользователь открывает бота, проходит короткий онбординг: форматы досуга,
   которые интересны, и текущий остаток баллов.
2. Дальше можно написать свободным текстом, что хочется («культурно провести
   субботу недорого») — бот (при доступности LLM) разбирает запрос в фильтры
   и присылает 2–3 карточки мероприятий с коротким объяснением, почему это
   подходит.
3. Кнопка «Открыть каталог» открывает мини-приложение с полным списком,
   фильтрами по формату/цене/поиску и возможностью сохранить мероприятие.
4. Внешний планировщик раз в день дёргает `/tasks/balance-reminders` —
   пользователям с непотраченными баллами в последние 45 дней года
   отправляется напоминание.

## Состав и архитектура решения

```
bot/         — Node.js/Express вебхук-бот (MAX Bot API)
  server.js  — сценарий диалога, онбординг, обработка сообщений
  events.js  — фильтрация тестового каталога мероприятий
  llm.js     — вызов LLM (Groq) для разбора запроса и персонализации,
               с фолбэком на правило-based логику
  maxApi.js  — обёртка над MAX Bot API (отправка сообщений/клавиатур)
  data/events.json — тестовый набор мероприятий (Пушкинская карта)
miniapp/     — статическое мини-приложение (HTML/CSS/JS, без сборки)
  index.html, style.css, app.js
  data/events.json — тот же тестовый набор, для офлайн-каталога
compose.yaml — запуск бота одной командой
```

Мини-приложение — самостоятельный статический сайт (подходит для
GitHub Pages/Vercel, бесплатно, HTTPS из коробки). Бот — единственный
компонент, которому нужен постоянно работающий сервер; для него подходит
бесплатный тариф Render/Fly.io.

## Запуск всех локальных компонентов через Docker

```bash
cp .env.example .env   # заполнить MAX_BOT_TOKEN (и опционально GROQ_API_KEY)
docker compose up --build
```

Поднимается один сервис `bot` на порту `3000`.

## Переменные окружения

См. `.env.example`:
- `MAX_BOT_TOKEN` — токен бота (выдаётся организаторами/в кабинете MAX)
- `MAX_API_URL` — базовый адрес MAX Bot API
- `MINIAPP_URL` — публичный адрес развёрнутого мини-приложения
- `GROQ_API_KEY`, `GROQ_MODEL` — опционально, для LLM-функций
- `PORT` — порт сервера бота
- `DEFAULT_CITY` — город по умолчанию, пока нет реальной геолокации

## Используемые порты

- `3000` — HTTP-сервер бота (вебхук `/webhook`, health-check `/health`,
  ручка напоминаний `/tasks/balance-reminders`)

## Зависимости

- `bot`: `express` — см. `bot/package.json` и зафиксированные версии в
  `bot/package-lock.json`
- `miniapp`: без зависимостей, ванильные HTML/CSS/JS

## Внешние сервисы и интеграции

- **MAX Bot API** — обязательная интеграция, реальная (`bot/maxApi.js`),
  домен `platform-api.max.ru`, токен передаётся заголовком `Authorization`.
  Подписка на вебхук — не настройка в кабинете, а вызов `POST /subscriptions`
  (запускается через `npm run set-webhook`, см. `bot/set-webhook.js`).
  Перед сдачей всё равно сверьте схему запросов/ответов с актуальной
  документацией dev.max.ru/docs-api — платформа развивается быстро.
- **Groq API** — опциональная интеграция для LLM-функций (бесплатный тариф).
  При отсутствии ключа или ошибке вызова бот работает по правило-based
  логике без деградации основного сценария.
- **Реальной интеграции с оператором «Пушкинской карты» нет.** Каталог
  мероприятий и баланс баллов — тестовые/вводятся пользователем вручную.
  Это явно показывается пользователю в футере мини-приложения.

## Работа с данными

`bot/data/events.json` (и его копия в `miniapp/data/events.json`) — вручную
подготовленный тестовый набор из 8 мероприятий в Казани с флагом
`pushkin_card: true`. Для реального запуска этот файл нужно заменить на
интеграцию с открытыми источниками (Культура.рф, региональные афиши) или
партнёрскую выгрузку данных от площадок.

## Порядок работы с тестовыми данными

Данные не требуют дополнительной подготовки — читаются напрямую из
`events.json` при старте бота и при загрузке мини-приложения.

## Пошаговый сценарий проверки

1. Задеплоить бота на публичный HTTPS-адрес, затем зарегистрировать вебхук —
   **в кабинете MAX нет отдельного поля для этого**, подписка делается
   вызовом API: `WEBHOOK_URL=https://<ваш-домен> npm run set-webhook`
   (внутри `bot/`) или напрямую curl-ом на `POST /subscriptions`
   (см. `bot/set-webhook.js`).
2. Написать боту любое сообщение — начнётся онбординг (форматы интересов,
   остаток баллов).
3. После онбординга написать, например: «хочу культурно провести субботу
   недорого» — должны прийти 2–3 карточки мероприятий.
4. Нажать кнопку «Открыть каталог» — должно открыться мини-приложение со
   списком мероприятий и рабочими фильтрами.
5. В мини-приложении нажать «Сохранить» на карточке — кнопка должна
   поменяться на «Сохранено».
6. Вызвать `POST /tasks/balance-reminders` вручную — должен вернуться JSON
   с числом отправленных напоминаний (0, если сейчас не в окне 45 дней до
   конца года).

## Примеры ожидаемого поведения системы

- Сообщение «музей» → бот присылает карточки категории «Музеи и выставки».
- Сообщение «баллы 1200» → бот подтверждает: «Баланс обновлён: 1200 ₽.»
- Запрос без результатов → бот отвечает, что ничего не нашлось, и
  предлагает открыть полный каталог.

## Известные ограничения

- Каталог мероприятий тестовый и статичный (без реальной интеграции).
- Баланс баллов вводится пользователем вручную, автоматической синхронизации
  с оператором «Пушкинской карты» нет.
- Состояние пользователей хранится в памяти процесса (`Map`) — перезапуск
  бота сбрасывает онбординг и сохранённые мероприятия; для продакшена нужна
  внешняя БД.
- Напоминания о сгорании баллов запускаются вручную/по внешнему крону, а не
  собственным постоянно работающим воркером (ограничение бесплатного хостинга).
- Кнопка «Открыть каталог» по умолчанию — обычная ссылка (`MINIAPP_MODE=link`).
  Чтобы она стала нативной кнопкой мини-приложения (`open_app`), нужно
  зарегистрировать HTTPS-адрес мини-приложения за этим ботом в кабинете MAX
  для бизнеса (business.max.ru/self → организация → бот → «Мини-приложения»),
  затем переключить `MINIAPP_MODE=native`.
- LLM подключается через Groq или OpenRouter (`LLM_PROVIDER`) — оба
  бесплатные, но с ограничениями по квоте/доступности; при сбое любого из
  них сценарий не ломается благодаря правило-based фолбэку.

## Порядок остановки и повторного запуска решения

```bash
docker compose down       # остановить
docker compose up --build # запустить заново
```

Состояние пользователей и сохранённые мероприятия при этом сбрасываются
(см. «Известные ограничения»).
